## 1. Git、GitHub とは？

### Git とは？

Git とは、ファイルのバージョン管理が簡単にできるツールです。

Git を利用することでコードの変更履歴を細かく記録したり管理する事が出来ます。

バージョンごとに管理することにより、新しいバージョンで不具合などが発生した場合に容易に変更履歴を確認したり、古いバージョンに復元することができます。

普段の大学のレポートなどでは最新版があれば困りませんが、プログラミングにおいてはチーム内のメンバーが同時に開発するため、バージョンを細かく管理することが非常に重要です。

必須：[テキスト：Git オレならこう説明する！Git 初心者への用語説明](https://qiita.com/nnahito/items/e546b27f73e7be131d4e)

### GitHub とは？

GitHub とは、Git を利用した開発者を支援する Web サービスです。Git はツールの名前で、GitHub は Web サービスの名前です。「メールと Gmail」や「動画と YouTube」の関係に似ています！

GitHub はコードのバージョン管理だけでなく、共同開発に向いています。プロジェクトチーム内でソースコードを互いに確認したり、コードをレビューしたり、機能や実装について議論を重ねたりすることが可能です。

GitHub アカウント 1 つあるだけで、1000 万人を超える世界中の GitHub ユーザーが書いたコードを見ることもできます。プロジェクト内や世界中の人とコミュニケーションを取ることのできる開かれた SNS とも呼ぶことができます。

## 2. ターミナルの基本

- Git、GitHub を使うためには、ターミナルの操作が必要になるので、ここで勉強しましょう！。

### ターミナルとは？

「ターミナル」は一般的に Mac にデフォルトで搭載されているアプリを指し、Windows の「コマンドプロンプト」とほぼ同じものです。ここから使っていくのは VSCode の「ターミナル」なので、そちらに名称を統一します！

ターミナルとは、コマンドと呼ばれる命令文を用いて PC の操作や設定をおこなうためのツールです。マウスやトラックパッドを用いず、キーボードで入力し、操作することができます。

ターミナルはあくまで操作画面を提供するアプリケーションで、実際コマンドを受け取ったり表示させているのは「シェル」という別のアプリケーションです。シェルはコンピュターと人間の仲介者のような立ち位置です。

### ターミナルの開き方

画面上部から「新しいターミナル」を選択すると、画面の下部にターミナルが表示されます！ここに様々なコマンドを打っていきます。

Mac では「Command + J」、Windows では「Ctrl + J」のショートカットで起動することもできます。

![terminal1](images/terminal1.png)

![terminal2](images/terminal2.png)

### コマンドを実行してみよう

ここでは基本的なコマンドをいくつか紹介します！

1. pwd を打ってみよう

- 現在作業しているディレクトリのフルパス（ファイル・フォルダの位置）を出力するコマンドです

  - ディレクトリ = フォルダ と捉えてもらえれば大丈夫です！

  ![terminal pwd](images/terminal-pwd.png)

- ここでは、「ユーザーフォルダ → kohei フォルダ → workspace フォルダ → sample-ph1-website フォルダ」という階層が確認でき、自分が今作業しているのが sample-ph1-website フォルダだと確認できます。

2. ls を打ってみよう

- ディレクトリの内容を表示するコマンドです

  ![terminal ls](images/terminal-ls.png)

- ここでは、sample-ph1-website フォルダ内には assets フォルダと、index.html というファイルが入っていることが確認できます。

3. cd を打ってみよう

- change directory の略で、作業ディレクトリを変更するコマンドです

  ![terminal cd](images/terminal-cd.png)

- 先ほどの assets フォルダ内に入るために、

  ```shell
  cd assets
  ```

  と入力しました。そこで改めて

  ```shell
  ls
  ```

  を実行すると、今度は assets 内に入っているフォルダを確認することができます。ファイル構造からも階層を確認できます。

  ![terminal files](images/terminal-files.png)

## 4. Git、GitHub 基礎知識

### よく出てくる単語一覧

- `リポジトリ`
  - リポジトリはある特定のプロジェクトのためのコードやドキュメント、リソースなどを保存・管理する場所
  - 「管理する場所 ≒ フォルダ」 だとイメージがしやすいかなと思います
- `リモートリポジトリ`
  - リモートリポジトリとは、インターネット上にあるサーバーに保存されているリポジトリのことを指します。GitHub や Bitbucket といったサービスがこれに該当します
- `ローカルリポジトリ`
  - ローカルリポジトリとは、あなたのパソコンの中に保存されるリポジトリのことを指します。これはあなたが自分のパソコン上で直接編集したり等をするための場所です
- `ブランチ`
  - プログラミングの世界で使われる概念で、ある特定の変更を行うために主要なコードラインから分岐した作業スペースのことを指します
  - 主要なコードラインは木の幹を表し、各ブランチはその枝を表します
- `コマンド`
  - コンピューターに対して特定の操作を行うために使用する指示を「コマンド」と言います
  - コマンドは、ターミナル等のツールを介して入力されます
  - ※ VSCode で「新しいターミナル」を実行すると OS 毎のツールが起動します
  - Windows なら PowerShell
    - [Windows で PowerShell を単体で起動する](https://www.billionwallet.com/windows10/windows10-powershell.html)
  - Mac ならターミナル（iTerm or Terminal）
    - [Mac でターミナルを単体で起動する](https://support.apple.com/ja-jp/guide/terminal/apd5265185d-f365-44cb-8b09-71a064a42125/mac#:~:text=Mac%E3%81%A7%E3%80%81%E4%BB%A5%E4%B8%8B%E3%81%AE%E3%81%84%E3%81%9A%E3%82%8C,%E3%82%92%E3%83%80%E3%83%96%E3%83%AB%E3%82%AF%E3%83%AA%E3%83%83%E3%82%AF%E3%81%97%E3%81%BE%E3%81%99%E3%80%82)
- `カレントディレクトリ`
  - カレントディレクトリとは、コンピュータのファイルシステムにおける現在位置、つまり「今いる場所」のことを指します
  - `cd`コマンドを使って今いる位置を移動することでカレントディレクトリの位置を変更することができます
  - カレントディレクトリを確認する方法もあるので、気になったら調べてみてください
- `ホームディレクトリ`
  - ホームディレクトリとは、コンピュータ上で各ユーザーが専用に持つディレクトリ（またはフォルダ）のことを指します
  - `cd` コマンドに移動先を指定せず実行するとホームディレクトリに移動できます

### 覚えてほしい Git コマンド一覧

- `git clone`
  - リモートリポジトリのブランチを複製してカレントディレクトリに保存する
  - (手元の PC のコマンドを実行した場所にリポジトリの内容を複製する)
- `git checkout {指定のブランチ}`
  - (`git switch {指定のブランチ}`)
  - 指定のブランチへ切り替え
  - switch コマンドは最近できたのでわからない先輩もいると思います。なので checkout をメインに覚えてもらっています
- `git fetch`
  - リモートリポジトリから最新のコミット（変更履歴）を取得します
  - ※ このコマンドはただリモートリポジトリの情報を取得するだけで、ワーキングディレクトリの内容（現在の作業）を変更・更新はしません
- `git push origin {指定のブランチ}`
  - ローカルの変更をリモートリポジトリにアップロード
- `git add {ファイル}`
  - ファイルをインデックスに追加する（コミットの対象にする）
- `git commit -m "{変更を記録するメッセージ}"`
  - インデックスに追加した変更を、ローカル or リモートリポジトリに記録する
  - 基本はローカルリポジトリ (手元の PC に複製してきた所) に記録すると思います
- `git pull origin {指定のブランチ}`
  - リモートリポジトリの内容を取得し、現在のブランチに取り込む（「fetch」と「merge」を行う）
  - ※ fetch と merge を覚えると覚える事項が増えるので後半の week で学習します！
- `git log`
  - コミットの履歴を表示する
- `git status`
  - ワークツリーにあるファイルの状態を表示する
  - ワークツリー ≒ Git 管理している作業フォルダー

### 5. Git を使ってみよう

1. `git clone [url]` コマンドを使って GitHub にあるリポジトリから手元の PC にクローンしてみましょう

- [練習用のリポジトリ](https://github.com/posse-ap/sample-ph1-github)
- clone に指定する url は GitHub の `Code` ボタンをクリックすると開きます
  ![GitHub Clone](images/github-clone.png)

- VSCode を利用した方法を載せるので困ったら見てください！
  ※ ホームディレクトリにクローンすると散らかってしまうので、POSSE で学ぶ用として `workspace` ディレクトリを新しく作成してそこにクローンするようにしています
  ![VSCode Clone](images/sample_clone.gif)
- クローンがうまくできないときは Discord で質問しましょう！メンターさんが駆けつけます！

2. GitHub 上で今回の練習用に 2 つ新しいブランチを作成しましょう

- sample-ph1-github のリポジトリのトップページからブランチ一覧ページへ移動しましょう
  ![GitHub Clone](images/github-branches.png)

- ブランチ一覧ページの「New Branch」のボタンをクリックして`main_0.0_name`と`feature_0.0_name`を main ブランチを「Source」として作成してください
- 規則としてはアンダーライン区切りで`main or feature` `期生` `名前` で作成してください
  ![GitHub Clone](images/github-branches-create.png)

3. `git fetch` コマンドを使ってリモートリポジトリの変更を取得しましょう
   - 新しいブランチを作成したことが変更点になるのでローカルリポジトリに反映のため取得します
4. `git checkout [新しい作業用ブランチ名]`コマンドを使って index.html の内容を変更して自分の紹介文に書き換えましょう

- 新しい作業ブランチ名は `feature_0.0_name` です
- (規則は main が feature にかわっただけで 2 の手順と一緒です)
- 13 行目に「名前」
- 14 行目に「大学と学年」「役職 (なくても良いです)」
- 18 行目の絵文字を自分の好きな絵文字に変更
- assets/img/me.png を 自分の画像に差し替える

5. `git add [file名]` コマンドを使って変更が完了したファイルをファイルをインデックスに追加してみましょう

- 今回指定するファイル名は index.html と ./assets/img/me.png になります

  ```shell
    $ git add index.html
    $ git add assets/img/me.png
  ```

  ※ $部分も含めてコピーすると動かないです

- `git add .` でカレントディレクトリ以下の修正があったファイル全てをインデックスに追加することができます
  - 一気に追加するのも便利ですが、今回は 1 つずつ追加する方法をとっています

6. `git commit -m "コミットメッセージ"` コマンドを使って、ステージングエリアの変更をコミットしてみましょう。

- commit とは最終チェックエリアの内容を確定させて登録すると覚えてください
- ※ commit するまでは変更が確定しないので、作業した内容がリモートリポジトリへ反映がされません。なのでコミット忘れなどに気をつけましょう

7. `git push` でコミットが完了した変更点をリモートリポジトリに反映させましょう

## 6. GitHub で Pull Request (PR) を使ってコードを反映してみよう

### 説明

今回は練習なので自身で作成したブランチ 2 つを使って反映させます

ただし、ハッカソンやチーム開発では

- 別の POSSE 生が作ったブランチ
- 全部のコードの集約地点として develop ブランチ

のどちらかを反映先に指定します

### チェック

1. GitHub で自分が作成したブランチで Pull Request (PR) を作成フォームまで進んでみましょう
   - [練習用のリポジトリ](https://github.com/posse-ap/sample-ph1-github) に移動しましょう
   - Pull Requests のタブを押して表示されたページで「New pull request」 をクリックしましょう
   - 「Compare changes」という変更点を比較するページが表示されるので、5-1-2 で作成したブランチを左側、5-1-4 で作成したブランチを右側に指定してましょう
   - 「Create pull request」のボタンが押せる状態になるのでクリックして作成フォームに移動しましょう
     ![Create Pull Request](images/github-pull-request-1.png)
2. Pull Request のタイトル、コメントを記載して Pull Request の作成を完了させましょう
   - テキストエリアが上部と下部にあるので上部を「タイトル」、下部を「コメント」とします
   - タイトル部分には変更内容の機能名やどういう変更かわかりやすい 1 文を指定してください
   - コメント部分には変更内容の詳細を書いてください

![Pull Request](images/github-pull-request-2.png) 3. Pull Request を指定のブランチに反映しましょう

- 反映先が正しいか確認しましょう

  - `main_0.0_name` from `feature_0.0_name` と自分が設定したブランチ名が上部に指定してあれば正しいです

- Pull Request の下の方にある「Merge pull request」ボタンをクリックして反映しましょう
  - 反映しても良いか確認されるので、問題なければ 「Confirm」をクリックしてください
    ![Pull Request](images/github-pull-request-3.png)

※ よく反映ミスが起きるときは反映先の指定が間違っていることがあるので反映前に確認するようにした方が安全です

## 7. 反映されたか確認してみよう

1. Github 上で反映されたか確認してみましょう

   - 1-2 で作成した PR が紫色で「Merged」と表記されてるか確認してみましょう
     ![Pull Request](images/github-pull-request-4.png)

   - VSCode に戻って反映の指定先にした `main_0.0_name` の命名規則のブランチに切り替えてからリモートリポジトリで反映された内容を取り込みましょう
     - 切り替えは `git checkout {指定のブランチ}`
     - 取り込みは `git pull origin {指定のブランチ}`
     - 切り替え -> 取り込みの順に実行しないと別のブランチに取り込んでしまうので注意です
