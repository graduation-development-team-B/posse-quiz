# Week01 プレビュー＋コード式ドリル

`Week01.md` のミニドリル3題を、それぞれ6問の順序付きステップとして収録。

| ドリル | ステップ順 |
| --- | --- |
| 映画カード | 土台 → ポスター → タイトル → 評価 → タグ → 再生ボタン |
| アーティストカード | 土台 → 写真 → 名前 → メンバーリスト → タグ → ボタン |
| イベント告知カード | 土台 → 写真 → ヘッダー → 開催情報 → タグ → ボタン |

HTML構造と本文は足場として用意し、各ステップで1箇所のclass属性を候補で編集する。正解したクラスは次のステップに残る。「実行する」と「解答を確定」は別操作で、編集後は再実行が必要。不正解でもコードを保持して再挑戦でき、最後の正解でドリルが完了する。

入口はWeek01の学習カード → ドリル選択。通常の3/5/10問のランダムセッションには混在させない。

## 現段階の実装

- `scripts/generate-week01-drills.js` が編集元。実行すると `mock-api/catalog.json` のWeek01問題のみを更新する。他の週と用語は保持する。
- 既存の候補選択型 `fillBlank` に `preview` メタデータ（ドリルID、版、順序、総数、ヒント、完成コード）を追加。
- PWAのsandbox iframeで描画。スクリプトと外部通信は禁止し、教材で使用するTailwindクラスの固定サブセットをローカルCSSで提供する。自由なTailwind環境ではない。
- 教材の写真がリポジトリに含まれていないため、同じローカル画像パスを代替SVGへ解決している。元のgoal.pngとのピクセル一致は検証対象外。
- 候補ID・実行時の候補ID・完了ステップ数を版別のlocalStorageに保存。同じ版の定義からコードを復元する。設定の学習記録削除で作業記録も削除する。
- 採点はクライアント側の候補ID照合。確定した正誤は既存の週別成績へ記録する。ドリルの再挑戦は専用画面から行う。

## Supabase導入時の境界

ドリル・教材版・順序付きステップをPostgreSQLで管理し、形式固有のコード・編集設定はjsonbで保持できる。進捗・作業コードは認証ユーザーと教材版に紐付け、RLSで本人の読み書きを制限する。公開定義から正答を分離し、サーバーが認証・版・現在ステップを確認して採点し、回答IDによる冪等性と進捗更新をトランザクションで保証する。現状のlocalStorage・クライアント採点はこの正式な認証・採点境界を実装したものではない。

クラスや問題文を変えるときはドリルのversionとcatalogのcontentVersionを更新する。正式な履歴表示には過去の教材版も保存する必要がある。
