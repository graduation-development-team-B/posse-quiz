**コミュニティの「ミニドリル」を、スマートフォンでコードと実行結果を確認しながら解ける学習アプリ**として、これまでの内容を要件に整理します。以下では、決定済みの前提と提案事項を分けています。

**1．目的・技術構成**

| 項目      | 要件                                                   |
| ------- | ---------------------------------------------------- |
| 目的      | スマホで気軽にプログラミング問題に取り組めること                             |
| 教材      | 所属コミュニティで使用している「ミニドリル」                               |
| 学習体験    | 自分のコードを見ながら、編集・実行・結果確認・回答確定ができること                    |
| フロントエンド | React Native                                         |
| バックエンド  | Node.js                                              |
| データベース  | PostgreSQL                                           |
| 教材で扱う技術 | HTML、CSS、Tailwind CSS、JavaScript、React、Git、Linuxコマンド |

**2．対応する4つの問題形式**

| 形式              | 機能                        | 主な採点対象                   |
| --------------- | ------------------------- | ------------------------ |
| ① 選択式           | 単一選択・複数選択・○×で回答する         | 選択した回答                   |
| ② プレビュー＋コーディング式 | コードを編集し、Webページの表示・動作を確認する | HTML構造、スタイル、操作後の状態       |
| ③ コーディング式       | JavaScriptを編集・実行し、出力を確認する | コンソール出力、関数の戻り値           |
| ④ ターミナル式        | コマンドや操作を実行し、ログと状態変化を確認する  | ファイル・Gitなどの状態、必要に応じて操作履歴 |

④には、現在のアプリにあるPRのbase・compare設定など、操作シミュレーションも含める案とします。

**3．教材・問題の構成案**

* 1つのミニドリルを、複数の短い「ステップ」に分割する。
* 各ステップに、問題文・学習目標・問題形式・初期コード・編集範囲・採点条件・ヒント・解説を設定する。
* 同じドリル内では、編集したコードを次のステップへ引き継ぐ。
* 学習途中のコードと進捗を保存し、再開できるようにする。
* ステップ開始時の状態へ戻せるようにする。
* 教材の更新後も回答履歴を確認できるよう、教材・問題を版管理する。

例：「割り勘計算ツール」は、入力欄作成 → 数値変換 → 計算 → イベント処理 → 入力チェック → 完成確認に分割します。

**4．入力・画面の要件**

| 項目      | 要件                                      |
| ------- | --------------------------------------- |
| 入力方法    | 穴埋め、トークン組み立て、部分編集、自由入力に対応する。行の並べ替えは追加候補 |
| 入力支援    | 記号・語句・クラス名の入力ボタン、削除、元に戻す、リセットを用意する      |
| コード表示   | 入力中も、前後を含めた完成形のコードを確認できる                |
| 編集範囲    | 問題ごとに編集可能な箇所と固定箇所を設定できる                 |
| 複数ファイル  | HTML・CSS・JS・JSXなどを切り替えて編集できる            |
| 結果表示    | プレビュー、見本、コンソール、達成条件を必要に応じて表示する          |
| スマホ対応   | キーボードや入力パネルで編集箇所が隠れない。プレビューを拡大できる       |
| フィードバック | 正誤に加え、未達成の条件やエラー内容を表示する                 |

②でもコンソールを利用できるようにし、Reactのkey忘れなど、見た目だけでは判断できない問題に対応します。

**5．実行・回答確定の要件**

| 操作    | 動作                      |
| ----- | ----------------------- |
| 実行する  | 現在のコードやコマンドを動かし、結果を確認する |
| 解答を確定 | 現在の回答を採点し、回答履歴・進捗を保存する  |
| やり直す  | 現在のステップ開始時の状態へ戻す        |

* 実行結果と、その実行に使ったコードを紐づける。
* 実行後にコードを編集した場合は、結果が編集前のものであることを示す。
* 構文エラー・実行時エラー・時間切れを区別して表示する。
* 正式な採点はサーバー側で行う。

**6．実行環境の要件**

| 対象                       | 必要な環境                                |
| ------------------------ | ------------------------------------ |
| HTML・CSS・画面操作用JavaScript | WebViewによるプレビュー                      |
| Tailwind CSS             | 教材の設定に対応し、追加したクラスが表示へ反映される環境         |
| React教材                  | JSX・import・複数ファイルを処理できるWeb用React実行環境 |
| 計算・アルゴリズム                | JavaScriptの実行結果・ログを取得できる環境           |
| Git・Linux・PR操作           | 状態を保持するシミュレーターを初期案とする                |

学習者のコードを実行する環境はAPI・DBから隔離し、実行時間・メモリ・出力量などに上限を設けます。React・Tailwindなどのバージョンは教材ごとに固定します。

**7．採点の要件**

* 原則として、模範コードとの文字列一致ではなく、要求された結果・動作を評価する。
* 特定の構文やクラスの使用が学習目標の場合は、その使用も確認する。
* 複数の正しい実装を許容する。
* 正解データ・非公開テストは、問題取得時に端末へ送信しない。

| 教材例        | 判定内容                      |
| ---------- | ------------------------- |
| アーティストカード  | 必要な要素、指定クラス、配置・装飾         |
| 割り勘計算      | 数値変換、切り上げ、表示更新、不正入力への対応   |
| MemberCard | propsを変更した際の表示追従、複数カードの表示 |
| key忘れ修正    | 適切なkeyの指定、一覧表示の維持、対象警告の解消 |
| ターミナル      | 目標状態への到達、必要な操作の実施         |

**8．保存するデータ**

* 教材・ドリル・ステップの定義と版
* 初期コード、画像、完成見本、実行環境の設定
* 正解・採点条件・テスト
* 学習途中のコードと操作状態
* 回答履歴、採点結果、学習進捗

共通項目は通常のカラム、形式ごとに異なる設定はPostgreSQLの`jsonb`で管理する案です。

**9．実装前に確定する事項**

| 項目         | 現時点の案・確認事項                      |
| ---------- | ------------------------------- |
| 初期の入力方法    | 穴埋め・トークン入力を優先し、自由入力の対応範囲を決める    |
| 学習モード      | ステップ式の練習に加え、支援を減らした仕上げ問題を設けるか   |
| ターミナルの対応範囲 | 最初に扱うコマンド・Git操作を決める             |
| 教材素材       | 元の初期コード、画像、`goal.png`、依存関係を用意する |
| 教材の不整合     | 「おやつ買い出しメモ」の説明とポイント計算の見本画像を統一する |

**初期実装案は、共通の問題画面・選択式・穴埋め／トークン入力を用意し、「割り勘計算ツール」1題を編集から採点・進捗保存まで完成させることです。**
