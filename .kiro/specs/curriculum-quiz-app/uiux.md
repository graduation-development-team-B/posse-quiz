# mikan UI/UX 分析レポート

英単語学習アプリ「mikan」iOS版の実画面8枚（教材一覧／教材詳細／学習設定／出題／即時復習／結果／学習データ）をもとに、UI・UXの特徴と画面設計の原則を分析したもの。

---

## 1. コア体験:「1回42秒」で閉じる学習ループ

分析画面のデータでは、**1セッション = 10問 / 解答時間34秒 / 当日の学習時間42秒**で「学習した日数1日」「連続学習日数1日」が成立している。ここに mikan の設計思想が凝縮されている。

```
教材を選ぶ → 条件を決める → 10問解く → 間違いを即復習 → 結果で称賛 → データで可視化 → 明日へ
   (選択)      (1タップ)     (30秒)      (その場で)      (2秒)        (継続動機)
```

**設計上の要点**

- 「学習の完了」を分単位ではなく**秒単位**で定義している。42秒でも「今日やった」という達成が記録され、連続日数が途切れない。
- ハードルの最小化＝離脱の最小化。学習アプリ最大の敵である「今日はもういいや」を、単位時間の設計だけで潰している。
- 1ループが短いため、**称賛→計測→次回誘導**のフィードバックを高頻度で回せる。

## 2. 情報アーキテクチャとナビゲーション

### 2.1 グローバルナビ（4タブ固定）

| タブ | 役割 | 心理的機能 |
|---|---|---|
| 教材一覧 | コンテンツの入口 | 「何をやるか」 |
| コーチ | 学習計画・伴走 | 「どう進めるか」 |
| 学習データ | 実績の可視化 | 「どれだけやったか」 |
| マイページ | 設定・アカウント | 「自分の管理」 |

- タブは**浮遊型のピル状バー**で、下端に常時固定。選択中タブのみアイコン＋ラベルをオレンジ着色＋背景ピルで強調し、現在地が一目で分かる。
- 4つに絞ることで「探す・学ぶ・振り返る・管理する」という学習行動の全体像がそのままメンタルモデルになる。
- 学習中（出題画面）と学習設定モーダルではタブバーが消える。**没入すべき画面からは離脱動線を意図的に取り除く**という徹底。

### 2.2 階層の深さ

```
教材一覧 ─ 教材詳細（チャプター/音声/電子書籍）─ 学習設定（モーダル）─ 出題 ─ 即時復習 ─ 結果
```

学習開始まで実質3タップ。さらに教材一覧トップの「**続きから (1)**」で階層をショートカットさせ、リピーターは1タップで前回の続きに戻れる。**新規ユーザーには探索、既存ユーザーには最短復帰**という二重動線。

## 3. 画面別の設計分析

### 3.1 教材一覧（ホーム）

- 最上部に検索、その直下に「人気ランキング／新着教材」の2ボタン。**検索できる人と探せない人の両方**を最初のスクロールで拾う。
- セクション構成は「ブックマーク（自分の弱点）→ 続きから（進行中）→ おすすめ教材」。**自分ごと化の強い順に上から並べる**優先順位。
- セクション見出しは2行構造:小さなグレーのキャッチ（`継続は力なり` / `期間限定でお試しできる`）＋大きな黒の機能名（`続きから (1)`）。**感情の言葉と機能の言葉を分離**して、可読性を落とさずトーンを出す手法。
- 件数を括弧で明示（`続きから (1)`、`AIと一緒に学べる問題集 (20)`）し、タップ前に中身の量を予測させる。
- 教材サムネイルは実際の書籍カバー。既知の参考書のビジュアルが**信頼性のショートカット**として機能し、説明文を不要にしている。

### 3.2 教材詳細

- ヘッダーに書影・タイトル・カテゴリタグ（TOEIC®）・`詳細情報 >`。書影の左上に**進捗バッジ「0%」**を重ね、一覧に戻っても進捗が読み取れる。
- 背景は書影から抽出したカラーのぼかし。教材ごとに空気感が変わり、**同一UIでも「別の本を開いた」感覚**を与える。
- タブ「チャプター／音声／電子書籍」で1教材の多様な使い方を横並びに提示。
- 最重要CTA `はじめる` は**2行構成**:「はじめる」＋「600点レベル 助走の400語 ①」。**動詞と目的語を分けて**、押した先で何が起きるかを迷わせない。
- チャプターリストは番号付き縦タイムライン＋**未開放は鍵アイコン＋グレーアウト**。順序性と「次の目標」を同時に示す。右端に `100問` のボリューム表示で所要時間を予測させる。

### 3.3 学習設定（ボトムシート型モーダル）

学習前の選択肢を**すべて1画面に集約**した、mikan で最も設計密度の高い画面。

- 上部:チャプター番号（円形プログレス）とタイトル、右に `内訳` リンク（詳細は必要な人だけ開く＝プログレッシブ・ディスクロージャー）。
- **出題範囲の選択**:`おまかせ 100問` / `保存済み 0問` / `未学習 100問` / `苦手 0問` の横スクロールチップ。各チップに件数が入り、**0問のものはグレーアウト**して選ぶ意味がないことを即座に伝える。
- **賢いデフォルト**:`おまかせ` が初期選択。さらに直下に「『おまかせ』とは？＝習熟度と学習日時をもとに、全単語を効率的に覚えられる順番で出題します」という**閉じられる説明カード**を配置。初心者には根拠を、慣れた人には非表示の自由を与える。
- **学習モードの選択**:`4択` / `カード` / `タイピング` /（`併記`）。デフォルトは最も負荷の低い4択。
- `スタート` は**画面下部に固定（スティッキー）**。設定を何度スクロールしても、開始動作は常に同じ位置。

> 原則:**選択肢は多く見せるが、決定は1つも要求しない。** 全項目に妥当なデフォルトがあり、何も触らず `スタート` を押せる。

### 3.4 出題画面

- 画面上部:`×`（中断）＋**プログレスバー**のみ。残量の可視化が完走率を支える。
- 中央の大きな白カード内に `1 / 10` と単語 `purchase`。**1画面1問・1タスク**の徹底。
- 選択肢は**縦積みの4つのピル**、各行に薄いグレーの通し番号（1〜4）。番号は視線の起点を作り、選択肢間の比較を高速化する。
- 選択肢は日本語訳のみで、余計な例文・品詞は出さない。**判断に必要な情報だけを残す**。
- `SKIP` ボタンをカードの外・右側に円形で配置。**「分からない」を正当な操作として用意**することで、詰まりによる離脱を防ぐ。
- 選択肢が2行に折り返す場合もピルの高さが伸びるだけで、**タップ領域は常に画面幅いっぱい**。片手・親指操作を前提としたヒットエリア設計。

### 3.5 即時復習（間違えた単語）

- **背景色をブルーに切り替え**て、正解フローのオレンジと明確に区別。ユーザーは色だけで「今は復習の文脈だ」と理解する。
- キャラクターは鉢巻き＋鉛筆の「Fight!」状態。**間違いを叱責ではなく応援に変換**する。
- 見出しは「すぐに復習して定着させよう」。**なぜ今やるのか（記憶の定着）を1行で言語化**して、スキップの合理性を下げる。
- 間違えた単語を2列グリッドで一覧化。長い訳語は `入手できる、利用できる、都合…` と省略し、**一覧性を訳語の完全性より優先**。
- CTAは `間違えた単語を復習 4問`（塗りボタン）と `結果画面へ`（テキストリンク）。**推奨行動を塗り、離脱は文字リンク**という視覚的重み付け。

### 3.6 結果画面

- 紙吹雪アニメーション＋称賛語「**偉才**」（ルビ付きの遊び）＋「**けたさん、かっこいいよ！**」。**ユーザー名を必ず差し込む**ことで、汎用の祝福を個人宛のメッセージに変える。
- キャラクターがキラキラを纏って登場。**成果の擬人化された受け手**がいることで、達成が対話的になる。
- 数値は白カードにまとめ、`わかった数 6/10` を最大サイズ、`解答時間 34秒` と `本日の累計 10問` を副次情報として区切り線で二分。**主指標1・補助指標2**の階層。
- 6/10という決して良くないスコアでも、称賛語のトーンは変わらない。**評価ではなく行動を称賛する**設計（＝続けることを強化する）。
- `次へ` の下に、スクロールで現れる `わからなかった (4)` セクション。1語ごとに音声再生・`苦手`ステータスの変更・ブックマーク追加が可能で、**結果画面が復習の起点も兼ねる**。

### 3.7 学習データ

- 冒頭にキャラクターからの一言「千里の道も一歩から！けたさんならできる！」。**数値の前に感情の導入**を置き、実績が乏しい初期ユーザーが数字を見て落胆するのを緩和する。
- `連続学習日数 1日` ＋ `自己ベスト更新中🔥`。**1日目から「更新中」と表現**することで、初日のユーザーにも守るべき資産を持たせる（＝損失回避の起動）。
- `お休みチケット ×2`（ⓘ付き）。**連続記録を失う恐怖に、逃げ道を制度として用意**。継続のプレッシャーが離脱に反転するのを防ぐ緩衝材。
- 週間バーチャート:今日を左端に置き、未来の日付は**破線の空円**、達成日は**塗りのチェック**。`目標 10` の破線ラインを引き、**埋めたくなる空白**をデザインしている。
- 指標カードは2列グリッド＋全幅カード。`学習した日数` `本日の学習時間` `合計学習時間` `覚えた単語数` `累計学習単語数` … と**「日数・時間・語数」の3軸**で同じ努力を何度も換算して見せる。数字が小さくても、どれか1つは必ず良く見える。
- `累計学習 単語数` には緑の `+ 10!!` という**増分表示**。総量ではなく変化量を強調するのが継続の燃料になる。
- 末尾に `シェア` ボタン。成果の外部発信＝自己コミットメントと自然流入の両取り。

## 4. ビジュアルデザインの原則

### 4.1 カラーシステム（意味に紐づいた色）

| 色 | 用途 | 意味 |
|---|---|---|
| オレンジ | 主要CTA・アクティブタブ・進捗・達成 | 前進、正、メインフロー |
| 淡いオレンジ（背景） | 結果・学習データ画面の地色 | 温かさ、祝福の場 |
| ブルー | 復習系ボタン・復習画面全体 | 訂正、冷静、やり直し |
| グリーン | `+10!!` などの増分、お休みチケット | 成長、獲得 |
| グレー | 未開放・0件・補助情報 | 「今は関係ない」 |
| ホワイトカード | あらゆる情報の器 | 情報の粒度の単位 |

**色が状態を語る**設計であり、テキストを読まなくても文脈が判別できる。特に「正＝オレンジ／復習＝ブルー」の分離は学習アプリとして秀逸。

### 4.2 タイポグラフィ

- **数値ファースト**:`42` `6/10` `1日` など、数字を極端に大きく、単位（秒・日・問）を小さく添える。視認の主役が常に成果になる。
- 見出しは太いゴシックで短く。本文の説明は必ず2行以内。
- カード内は「**小さなラベル（左上）＋巨大な値（右下）**」という一貫した型。全カードが同じ読み方で処理でき、走査コストがゼロに近い。

### 4.3 レイアウト／コンポーネント

- **カードベース**:すべての情報が角丸の白カードに収まり、余白で区切られる。境界線をほぼ使わず、影と余白で階層を作る軽量な印象。
- **角丸の徹底**:カード・ボタン・チップ・タブバーまで大きめの角丸で統一。柔らかさ＝「勉強のつらさ」の中和。
- **サム・ゾーン設計**:主要CTAは常に画面下部。上部にあるのは中断（×）と情報（…）のみ。
- **横スクロールチップ**:出題範囲や学習モードなど、選択肢が増えても縦の長さを消費しない。ただし右端で見切れさせて「まだある」ことを示唆。
- **2列グリッド**:指標カード・復習単語など、同列の情報は必ず2列。一覧性とタップサイズのバランス点。

## 5. マイクロコピーとトーン

- **ユーザー名の常時差し込み**:「けたさん、かっこいいよ！」「けたさんならできる！」— テンプレートを会話に変える最小コスト。
- **称賛は大げさに、評価は控えめに**:「偉才」「よっ」といった講談調の遊び。スコアの良し悪しに触れず、行動そのものを褒める。
- **命令ではなく誘い**:「すぐに復習して定着させよう」「保存した単語・フレーズから復習しよう！」— `〜しよう` 形の統一で強制感を消す。
- **機能名を平易な日本語に**:`おまかせ` `お休みチケット` `続きから` `苦手`。専門語（アルゴリズム、ストリークフリーズ）を一切使わない。
- **ことわざ／慣用句の活用**:「継続は力なり」「千里の道も一歩から」— 学習文化の共通言語に接続し、説得コストを下げる。

## 6. 行動デザイン（ゲーミフィケーション）

| 仕掛け | 実装 | 効いている心理 |
|---|---|---|
| 連続学習日数 | `1日 / 自己ベスト更新中🔥` | 一貫性、損失回避 |
| お休みチケット | ×2の消費型アイテム | 記録喪失の恐怖の緩和、復帰許容 |
| 目標ライン | 週間チャートの `目標10` 破線 | ツァイガルニク効果（未完了の不快） |
| 未来の空円 | 破線の空チェック | 埋めたくなる空白 |
| 増分表示 | 緑の `+10!!` | 進捗フィードバック |
| 称賛演出 | 紙吹雪＋称賛語＋キャラ | 即時報酬 |
| キャラクター | みかんの精 | 学習の擬似伴走者、感情の受け皿 |
| シェア | 結果の外部共有 | 公的コミットメント／拡散 |
| 多軸カウント | 日数・時間・語数・問題数 | 少ない努力でも「何かが増える」 |

**要点:報酬は正答率ではなく「実行」に紐づいている。** 6/10でも紙吹雪が出る。学習アプリで最適化すべきKPIが「正確さ」ではなく「明日も開くこと」であると理解した設計。

## 7. 収益化UX（フリーミアムの見せ方）

- **72時間の全機能無料**:「インストールしてから72時間 (08/28 14:44まで) はすべての教材・機能が無料でお試し可能！」と**具体的な日時まで明示**。抽象的な「期間限定」より強い期限効果。
- **P（Premium）バッジ**:`タイピング` モード、`SKIP`、ブックマークの一部に小さな有料バッジ。**機能を隠さず、触れる位置に置いて可視化**する。「使えない」ではなく「まだ開いていない」と感じさせる。
- **ロック済みチャプター**:鍵アイコン付きで一覧に並べ、コンテンツ量の豊富さそのものを訴求。
- **書影上のPremiumリボン**:教材単位で有料範囲を示し、無料/有料の境界を学習前に理解させる。
- **セールバナー**:「24時間限定SALE 最大55%OFF」を学習データ画面上端に表示。

> **注意点**:このバナーはステータスバー（時刻・電波）に重なる位置に表示され、システム領域を侵食している。緊急性の演出としては強いが、**OSのUIと競合する広告表示はダークパターンと見なされるリスク**がある。参考にする場合はセーフエリアを尊重した実装を推奨。

## 8. 抽出できる画面設計原則（10箇条）

1. **1画面1目的**:出題画面には単語と選択肢しかない。目的外の要素は消す。
2. **主要CTAは下部・1つ・2行**:「動詞＋対象」で結果を予告し、常に親指の届く位置に固定する。
3. **賢いデフォルトを置き、選択を任意にする**:全項目に推奨値があり、無操作でも開始できる。
4. **色に意味を割り当てる**:オレンジ＝前進、ブルー＝復習、グリーン＝増加、グレー＝対象外。
5. **数値は巨大に、単位は小さく**:成果を視認の主役にする。カードは「ラベル＋値」の同一フォーマットで統一。
6. **状態を先回りして伝える**:件数、進捗%、鍵、0問グレーアウト。タップ前に結果が分かる。
7. **失敗の直後に回復動線を置く**:間違いは結果より先に「即時復習」へ。文脈を色で切り替える。
8. **称賛は行動に、評価は控えめに**:スコアで態度を変えない。名前を呼ぶ。
9. **継続の資産と、その保険をセットで渡す**:ストリーク＋お休みチケット。プレッシャーだけを与えない。
10. **完了の単位を極小にする**:10問・30秒。「今日はもう無理」を成立させない粒度に設計する。

- [ ] コアループの1周が3タップ以内で始まり、明確な祝福で終わっているか?
- [ ] リピーター向けの「続きから」ショートカットがホーム上部にあるか?
- [ ] 設定画面は「何も選ばずに始められる」か?
- [ ] エラー／失敗の直後に、回復のための動線が最短距離で置かれているか?
- [ ] 主要CTAは画面下部に固定され、1画面に1つに絞られているか?
- [ ] 進捗を複数の軸（回数・時間・量）で換算し、必ず1つは伸びて見えるようにしているか?
- [ ] 増分（+N）を見せているか? 総量だけになっていないか?
- [ ] 有料機能を「隠す」のではなく「見えるが未開放」として提示しているか?
- [ ] 継続のプレッシャーに対する逃げ道（休止の許容）を用意しているか?

## 10. 改善余地・議論点

- **広告バナーのセーフエリア侵食**:学習データ画面上部のSALEバナーがステータスバーに重なり、時刻表示と衝突している。短期CVRと引き換えに信頼を損なうトレードオフ。
- **称賛の摩耗**:紙吹雪と称賛語は高頻度で反復されるため、数十セッション後には価値が減衰しやすい。段階的な演出のバリエーションや、達成度に応じた変化が必要。
- **成果指標の水増し感**:「合計学習時間42秒」「累計学習単語数10」など、初期は指標の粒度が細かすぎて逆に少なさが目立つ。初期ユーザーには指標カード数を絞る出し分けも一案。
- **横スクロールチップの発見性**:`苦手` チップが右端で見切れており、弱点復習という価値の高い機能が気づかれにくい可能性がある。
- **6/10という結果の扱い**:正答率へのフィードバックが実質ないため、「解いているが伸びていない」状態を検知しづらい。コーチタブ側で補完していると推測されるが、結果画面にも弱い示唆があってよい。

# POSSE Quiz 主要学習ループ UI/UX 契約

## 11. 適用範囲と再設計方針

本章は、参考画像から抽出したレイアウト、情報階層、色の意味、短時間で完了できる操作感を、POSSE Quizの教材・用語・学習状態に合わせて再設計するためのビジュアル/インタラクション契約である。mikanのブランド、キャラクター、教材画像、固有の文言、画面構成をコピーせず、POSSE Quiz固有の日本語ラベル、Week情報、学習進捗を表示する。

今回反映する範囲は、**ホーム、学習設定（既存のscope画面）、クイズ、Feedback、結果**の5画面による主要学習ループに限定する。既存のContent_API、Content_Cache、Progress_Store、QuizSession、Answer_Judgeのドメイン/API/進捗挙動は変更せず、画面構成、表示モデル、導線、スタイル、アクセシビリティをUI層で整える。

## 12. 5画面のビジュアル/インタラクション契約

### 12.1 ホーム: 教材を探して今日の一歩を始める

**目的**: Learnerが現在の学習状態を短時間で把握し、1〜3回の操作でWeekの学習設定へ進める。

**情報階層と配置**

1. 画面上部に、検索風の教材探索導線を置く。入力検索を実装しない場合も、虫眼鏡アイコンと「教材を探す」などの日本語ラベルで範囲選択への入口を明確にする。
2. 探索導線の下に、POSSE向けの補助導線として「おすすめの学習」と「新着教材」またはAPIカタログ上の同等情報を表示する。存在しないデータを作らず、利用可能なWeekへのショートカットとして扱う。
3. 「今日の一歩」カードを上位に置き、現在の推奨Week、問題数、開始CTAを1枚の白カードにまとめる。推奨が決められない場合は、最初に利用可能なWeekを選択する導線を表示する。
4. 続きのSessionや前回選択範囲が存在する場合は「続きから」カードを表示し、同じ範囲・問題数でscope画面へ復帰できるようにする。存在しない場合はカードを生成しない。
5. Week教材カードはWeek番号、教材タイトル、出題可能な問題件数、正答率または「未学習」、出題開始の押下領域を含める。week3〜week6を教材内の順序で表示し、補助情報は小さく、開始行動を主役にする。

**インタラクション**

- 検索風導線、「今日の一歩」、「続きから」、Weekカードはscope画面へ遷移する。
- 教材取得中でも既存Cacheの表示を優先し、SyncStateはカード内の補助表示として扱う。API/cache/domain behaviorをUI仕様から変更しない。
- 教材が利用できない場合は、日本語の取得エラーと「再試行」を表示し、範囲選択やクイズ開始のCTAは無効化する。
- カード全体を押下可能にする場合も、ラベル、選択対象、遷移先がスクリーンリーダーで識別できるようにする。

### 12.2 学習設定: scope画面をボトムシート風に再構成する

**目的**: 出題範囲と問題数を確認し、何も変更しなくても学習を開始できる状態を作る。

**ビジュアル契約**

- 既存の`app/scope/index.tsx`を、画面下部からせり上がるボトムシート風のレイアウトとして扱う。Web/大画面では中央寄せの最大幅コンテナ内にシートを表示し、モバイルでは画面幅に合わせる。
- 上部にドラッグハンドル相当の視覚的なシート境界、Weekの概要、選択中の件数を置く。ドラッグ操作自体は必須にせず、戻る操作と明示的な閉じる操作を提供する。
- 出題範囲は横スクロール可能なチップで表示し、例として「Week03」「Week04」などPOSSE向けの名称を使用する。各チップに出題可能件数を付ける。
- 0問の範囲はグレーアウトし、押下不可とする。選択中チップはオレンジの背景または境界で示し、テキストだけに依存しない。
- 問題数は3/5/10問の選択肢として表示し、既存の設定値がない場合は5問を初期選択にする。不正値はUI上で表示せず既存ロジックの既定値へ戻す。
- 「スタート」または「学習を始める」の主要CTAはシート下部に固定する。内容がスクロールしてもCTAの位置とラベルを変えない。

**インタラクション契約**

- 初期状態は有効なWeekと出題数が選択され、開始CTAを押すだけでSessionを生成できる。
- 出題範囲はWeek単位で決まる。選択Week数と出題可能問題数は操作ごとに即時更新する。
- 0件、Week未選択、横断選択の不正状態では開始せず、日本語メッセージと選択画面へ戻る操作を表示する。直前の選択状態は保持する。
- scopeから戻った場合は、直前のWeek/問題数選択を復元する。

### 12.3 クイズ: 1問1目的の没入型学習画面

**目的**: 補助情報を抑え、問題を読んで回答する一つの行動に集中させる。

**ビジュアル契約**

- ヘッダーは戻る/中断操作と進捗表示に限定する。通常の下部ナビゲーションは表示しない。
- 進捗は「1 / 5」形式の番号と細いプログレスバーで示し、残りの量を常に把握できるようにする。正解数は補助情報として小さく表示してよい。
- 問題文は白カード1枚に収め、カード内の主見出しとして表示する。1画面に複数の問題や長い説明を同時に置かない。
- 選択肢は全幅に近い縦積みのPressableとし、各行の左側に1〜4または指定された選択肢番号を表示する。長い文は折り返し、押下領域を縮めない。
- バグ診断のコードは等幅ブロック内で横スクロールさせ、画面全体の横スクロールを発生させない。
- 自由入力穴埋めでは入力欄と確定CTAをカード下部にまとめ、空文字・空白のみの状態では確定CTAを無効化する。
- 色、装飾、説明文は回答判断に不要なものを抑制し、問題文、入力、選択肢、確定操作を主役にする。

**インタラクション契約**

- 選択肢は1件だけ選択でき、選択状態は色・境界・記号・accessibilityState.selectedで表現する。
- 回答確定後は同じQuestion_Itemの再回答を受け付けず、Feedback状態へ切り替える。
- 中断操作には確認を挟み、確定済み回答だけを既存Progress_Storeへ渡す。未解答は集計しない既存要件を維持する。
- Resizeや画面遷移で入力途中の選択状態を失わない。Session内の選択肢順は既存optionOrdersを使用する。

### 12.4 Feedback: 誤答を回復行動へつなげる

**目的**: 正誤を即時に理解し、正解・解説・出典を読んだあと、必要なら復習へ進める。

**ビジュアル契約**

- 正解状態はオレンジ/淡いグリーン系、誤答状態はブルー系の補助背景またはアクセントで区別する。正誤を色だけで判断させず、「✓ 正解」「! 誤り」などの記号と日本語ラベルを併記する。
- 問題文と判定結果を同じ画面の上部に置き、回答内容と正解内容を白カード内で比較できるようにする。
- 解説全文と、Source_Referenceを「引用：Week03「見出し」」の1行で示す情報ブロックを白カード内に配置する。解説は省略せず、長い場合は画面スクロールで全文に到達できるようにする。
- 誤答時に誤り理由が存在する場合は、正解内容と区別できるブルー系の「なぜ違う？」ブロックで表示する。理由がない場合は空の領域を作らない。
- 「復習に追加」または既存の「あいまい」操作を、復習文脈のブルー系CTAとして配置する。登録済み後は受理済み表示と無効状態に切り替える。
- 「次へ」は主要な継続CTAとして画面下部に固定または常に視認可能にし、最終問題では結果画面へ遷移することをラベルで示す。

**インタラクション契約**

- 判定結果表示中は選択肢と回答確定操作を無効化する。
- Term_Entryへのリンクは、解説中の対応用語の最初の一致だけをリンク化する既存ロジックを利用する。
- 「次へ」は未出題問題があれば次問、なければ結果へ遷移する。Feedbackから用語詳細へ遷移して戻ってもSessionの問題番号、正解数、Feedback状態を保持する。
- ライブリージョンは表示時に正誤と正解を1回だけ通知する。

### 12.5 結果: 行動の完了を称賛し次の一歩を示す

**目的**: セッション完了を明確に伝え、スコアにかかわらず再挑戦・復習・ホームへの次の行動を選べるようにする。

**ビジュアル契約**

- 画面全体は淡いオレンジ系の達成背景と白カードで構成し、学習完了を視覚的に区切る。固有キャラクターや著作物は使用しない。
- 見出しは「学習完了」「今日の一歩を達成」など、POSSE Quizの行動を称賛する日本語にする。ユーザー名を挿入しない。
- 主指標は「正解数 / 総問題数」を最も大きく表示し、補助指標として「解答時間」「復習対象件数」または既存結果モデルが提供する同等の値を小さく分けて表示する。
- 誤答したQuestion_Itemの一覧、全問正解表示、復習対象件数など、結果に基づく情報は白カード内で整理する。数字、単位、ラベルの階層を統一する。
- 主要CTAは「もう一度挑戦」、次点のCTAは「間違いを復習」、退出導線は「ホームへ」のテキスト/アウトラインボタンとする。Review_Queueが0件の場合は復習CTAを無効化する。

**インタラクション契約**

- 再挑戦は直前Sessionと同じ範囲・問題数でscopeまたは新規Sessionへ進む既存導線を利用する。
- 復習CTAはReview_Queueに対象がある場合だけ有効にし、対象がなければ理由を補助テキストで示す。
- 結果画面の表示をProgress_Snapshot保存完了でブロックしない。既存の保存タイミングと失敗時のメモリ保持を維持する。
- ホームへ戻る操作では、直近の範囲や続きから情報を必要に応じて表示するが、新しいドメイン状態を作らない。

## 13. 共通ビジュアルトークンと操作契約

### 13.1 色の意味

| トークン | 用途 | 表現 |
|---|---|---|
| `progressOrange` | 前進、選択中、主要CTA、進捗 | ホーム/設定/クイズ/結果の主導線 |
| `reviewBlue` | 復習、誤答理由、復習CTA | Feedbackと復習行動の文脈 |
| `growthGreen` | 成長、増分、完了補助 | 正答率の増加や追加状態。ただし正誤判定は記号/文言も併用 |
| `supportGray` | 補助情報、未選択、0件、無効 | disabled、説明、単位、非活性チップ |
| `surfaceWhite` | 情報カード、選択肢、結果指標 | 背景との差と余白で階層を作る |

ライト/ダーク配色では同じ意味を保ったままコントラストを確保し、色値を直接画面へ散在させず、既存theme定数に集約する。

### 13.2 形状・レイアウト

- 白カード、チップ、ボタン、選択肢は一貫した角丸を用い、境界線より余白と面の差で階層を表現する。
- 主要CTAは画面下部または親指の届く位置に置き、1画面につき最重要CTAを1つに絞る。
- タップ可能要素は44pt×44pt以上、隣接要素間は8pt以上とする。無効状態でもラベルと理由を支援技術へ伝える。
- 320〜767pxでは1カラム・横overflowなし、768〜1023pxでは中間レイアウト、1024px以上では最大960pxの中央コンテナとする既存要件を5画面に適用する。

### 13.3 アクセシビリティと日本語

- 見出し、ボタン、タブ、選択肢、カードの操作目的を日本語のaccessibilityLabelで示す。
- 選択中、無効、正解、誤り、復習登録済みの状態をaccessibilityState、記号、日本語テキストの組み合わせで通知する。
- WebではTab/Enter/Spaceと可視フォーカスを提供し、Feedbackのライブリージョンは1回だけ通知する。
- 参考画像の英語UIをそのまま移植せず、コード片・予約語以外の画面文言を日本語にする。

## 15. 画面別検証観点

- ホーム: 教材探索、今日の一歩、続きから、Weekカード、教材取得エラー、SyncState補助表示。
- 学習設定: ボトムシート風レイアウト、範囲チップ、件数、0件無効、問題数初期値、固定開始CTA、選択復元。
- クイズ: 没入型ヘッダー、進捗、1問1カード、形式別入力、全幅選択肢、回答確定後の無効化。
- Feedback: 正誤色分離、記号/日本語ラベル、正解、解説全文、出典1行、誤答理由、復習登録、次へ。
- 結果: 完了メッセージ、主指標/補助指標、誤答した問題の一覧、再挑戦/復習/ホーム、復習0件無効。
- 共通: 日本語、ライト/ダーク、44pt操作領域、8pt間隔、キーボード、可視フォーカス、横overflowなし、参考画像固有要素の不使用。
